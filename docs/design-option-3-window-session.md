# 方案 3：窗口会话式地编（Window-hosted Session）

> **状态：候选方案，尚未选定。** 与[方案 1：拼装模式](ue5-level-editor-mode-design.md)、[方案 2：免切换放置](design-option-2-modeless-placement.md)并列，由项目负责人后续选择。
> **目标引擎：** UE 5.7。未在引擎中验证，手感和实现成本靠 P0 原型确认。
> **一句话：** 地编会话寄生在模块库窗口的「地编」Tab 上——Tab 打开即激活，Tab 关闭或 `Esc` 即结束；UE 编辑模式全程不变（保持 Select）。

## 架构

```
模块库窗口（SDockTab，常开可停靠）
├── Tab「模块库」：筛选 / 卡片 / 3D 预览（方案 1 v2 §3.1，不变）
└── Tab「地编」（新增）
    ├── FModuleEditSession：Idle / Placing / Picking；由 Tab 可见性与 Esc 驱动
    ├── SModuleEditOverlay：挂到活动视口；左键与快捷键接管，其余事件透传
    ├── 复用 FModulePlacementService：邻接 / 表面 / 网格求解（方案 1 v2 §4）
    └── 整理区：对齐 / 等距分布 / 沿街面对齐 / 选中同款 / 替换（无模式依赖）
```

## 会话状态机

- **Idle**：Tab 打开但未选模块。overlay 只响应吸管与快捷键，不拦截左键。
- **Placing**：从卡片拖出或点"放置"。ghost 跟随光标，左键放置；"连续放置"开关控制单次/连续；`Esc` 回 Idle（不关 Tab）。
- **Picking**：吸管激活。下一次左键拾取场景模型 → 定位到对应卡片 → 回 Idle。
- **结束**：Tab 关闭/切走、`Esc` 在 Idle 下、点"结束会话" → 移除 overlay，toast 提示。

## Overlay 接管 / 透传矩阵

| 输入 | 会话激活时 | 说明 |
|---|---|---|
| 左键按下 | 接管：放置 / 拾取 | 标记 Handled |
| 左键拖拽 | 透传 | 只拦截"按下"瞬间，拖拽（Gizmo/框选）交给下层 |
| 右键 / 中键 / 滚轮 | 透传 | 导航必须与原生零差异，P0 实测 |
| `R` / `[` / `]` / `Esc` | 接管 | 输入框聚焦时不吞（先检查焦点） |
| `Ctrl` | 透传 | 预留"按住临时关闭吸附"，快捷键冲突待核对 |

## 吸附规则

沿用方案 2，优先级：插槽（数据中有才用）→ 邻接（包围盒边/面贴合，墙/窗/门）→ 表面（植物/灯具等不规则模型）→ 网格（当前步长）→ 自由（`Ctrl` 临时关闭，待核对冲突）。

视口只显示当前吸附类型 + 绿/蓝状态色。设置只保留总开关与网格步长，其余进"高级"。

## 状态可见性（三件套，缺一不可）

1. **视口底部状态条**（overlay 绘制）：当前模块、`R` 旋转、`[` `]` 换款、`Esc` 退出、当前吸附类型。
2. **Ghost 本身**：绿 = 插槽/邻接命中，蓝 = 网格，无色 = 自由。
3. **窗口标题**：会话激活时显示绿点 + "地编会话中"。

## 数据

沿用方案 2：

- 必需：`id`、`asset_path`、`display_name`、`category`、`tags`。
- 可选：`sockets`、`front_plane`、识别置信度（低置信度卡片标"待确认"，照常可用）。
- 人工修正存独立覆盖文件，加载优先；重扫不冲掉人工修正。
- 尺寸与 pivot 从模型实时读取，不依赖注册数据。

## 整理操作

沿用方案 2，全部走事务、一次撤销：

- 对齐（X/Y/Z 六向）、等距分布、**点面式沿街面对齐**（点基准模型的面，其余沿该面法线对齐；处理十字路口多朝向与单选基准问题；模型带招牌等凸出物时包围盒可能有偏差）。
- 一键选中同款 / 同类；替换（位置旋转保持不变）。

## P0 验证清单（约 3 天）

1. **自管拖拽**：拖拽全程 ghost + 吸附预览；松手结果与预览一致；一次放置一次撤销；`Esc` / 拖出视口不残留 Actor。（方案 1 v2 §2.3）
2. **Overlay 透传**：右键 orbit、中键 pan、滚轮缩放与原生零差异；左键拖拽（Gizmo/框选）不受影响。
3. **按键与焦点**：搜索框聚焦时 `R` / `[` / `Esc` 不被吞；`Esc` 退出优先级正确（会话 > 取消选择）。
4. **Gizmo 变换结束监听**：验证 release 后吸附是否可靠；不可靠则第一版砍掉该需求（放置时吸附保留，Gizmo 保持原生）。
5. **多视口策略**：只给活动视口挂 overlay，确认切换视口时行为正确。

任一项不通过 → 回退对应降级项，不推翻方案。
